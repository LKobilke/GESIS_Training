Introduction to R

10 Tutorial: Writing a Reproducible APA 7 Paper with Quarto and Zotero

This tutorial shows you how to write an academic paper in RStudio while keeping your text, citations, analyses, tables, and figures connected in one reproducible workflow.

You do not need to know Quarto, Markdown, or YAML before starting. We will introduce each of these only when you actually need it.

After working through this tutorial, you’ll be able to…

  • create a Quarto paper in RStudio and turn it into a finished document
  • understand what terms such as YAML, Markdown, code cell, and render mean
  • write mostly in RStudio’s Visual Editor instead of memorizing Markdown syntax
  • insert citations directly from Zotero
  • produce an APA 7 manuscript with apaquarto
  • connect values in your text to your R analysis so that they update automatically
  • create reproducible tables, figures, and cross-references
  • organize a paper as an RStudio Project without using setwd()

10.0.1 The basic idea

Think of a Quarto paper as a Word document that can also contain R code.

You write your paper, add citations, and place analyses where they belong. When you click Render, Quarto creates the finished Word, HTML, or PDF document for you.

10.1 Create and understand your first Quarto document

10.1.1 Create an RStudio Project for your paper

Before creating the paper itself, create an RStudio Project. A project gives your paper a clear home folder and makes file paths much easier to manage.

In RStudio, choose:

File > New Project...

Create a new project in a folder such as:

my-paper/

At the beginning, that folder does not need to contain much:

my-paper/
├── my-paper.Rproj
└── paper.qmd

Later, it might grow into something like this:

my-paper/
├── my-paper.Rproj
├── paper.qmd
├── references.bib
├── data/
│   └── WoJ_names.csv
├── R/
│   └── functions.R
└── figures/

The important principle is simple: keep the files belonging to the paper inside the same project folder. Then you do not need setwd() inside your paper.

10.1.2 Create a Quarto document

With your project open, choose:

File > New File > Quarto Document...

Give the document a temporary title and choose HTML as the output format for now. HTML is convenient while learning because it renders quickly.

Save the document as:

paper.qmd

The file ending .qmd simply means Quarto document.

10.1.3 What is Quarto?

Quarto is a system for combining ordinary writing, citations, R code, tables, and figures in one source document. It is the successor to the R Markdown workflow.

10.1.4 Start in Visual mode

At the top of the editor, RStudio lets you switch between Visual and Source mode.

For this tutorial, start with Visual mode.

Visual mode behaves much like a simple word processor. You can write paragraphs, create headings, insert links, add citations, and make lists without knowing Markdown syntax.

Type a few sentences into the document, for example:

This is my first Quarto paper. Eventually, this document will contain my text, analyses, tables, figures, and references.

You do not need to understand everything else that RStudio placed in the file yet.

10.1.5 Render the document once

Click Render at the top of the editor.

Rendering means that Quarto takes the source file and produces the finished document. Depending on your settings, that finished document might be HTML, Word, or PDF.

For example:

paper.qmd  →  Render  →  paper.html

Later in this tutorial we will change the output to an APA-style Word document.

This is an important first milestone: if you can edit paper.qmd and click Render successfully, your basic Quarto setup works.

10.2 What is actually inside a .qmd file?

Now that you have already created and rendered a Quarto document, it is useful to understand what is happening behind the scenes.

Switch from Visual to Source mode.

A very small Quarto document might look like this:

---
title: "My first Quarto document"
format: html
editor: visual
---

This is ordinary text in my paper.

```{r}
WoJ %>% tidycomm::describe()
```

There are three main parts:

  1. YAML header = settings for the document
  2. Markdown = the written content and simple formatting
  3. Code cells = R code that Quarto can run

You do not need to become an expert in any of these to use Quarto effectively.

10.2.1 What is YAML?

YAML is the small settings block at the very top of a Quarto file. It begins and ends with three dashes:

---
title: "My first Quarto document"
format: html
editor: visual
---

It is not R code. Think of it as the document’s settings menu written as text.

In this example:

  • title: tells Quarto the title of the document
  • format: tells Quarto what kind of output to create when rendering
  • editor: tells RStudio which editing mode to open by default

You will sometimes see settings nested underneath another setting:

format:
  apaquarto-docx: default

The indentation is meaningful, so it is best not to randomly add or remove spaces in YAML.

10.2.2 A beginner rule for YAML

You do not need to write a YAML header from memory. Usually, you start from a working example and change only things such as the title, authors, abstract, or output format.

10.2.3 What is Markdown?

Markdown is a lightweight way of marking up ordinary text. In Visual mode, RStudio handles most of this for you.

For example, in Source mode you might see:

What you want Markdown underneath
Heading # Heading
Subheading ## Subheading
Italics *text*
Bold **text**
Bullet list - Item
Numbered list 1. Item
Link [link text](https://example.org)
Image ![Alt text](figures/myfigure.png)

You do not need to memorize this table. If you prefer, create these elements in Visual mode and occasionally switch to Source mode to see how they are stored.

10.2.4 What is a code cell?

A code cell is a section of the document containing code that should be executed when the document is rendered.

An R code cell looks like this:

```{r}
WoJ %>% tidycomm::describe()
```

The {r} tells Quarto that the contents should be run as R code.

This is what makes a Quarto paper reproducible: your statistical analysis can live in the same workflow as the sentence that reports its result.

10.2.5 What does Render do?

When you click Render, Quarto roughly does the following:

  1. reads the settings in the YAML header
  2. runs the code cells that should be executed
  3. combines your text with the generated results, tables, and figures
  4. processes citations and cross-references
  5. creates the final HTML, Word, or PDF document

That is why changing the data and rendering again can update the entire paper.

10.3 Add references with Zotero

10.3.1 Connect Zotero

If you already use Zotero, keep your references there as usual. If not, install Zotero Desktop first.

When RStudio Desktop and Zotero Desktop are running on the same computer, RStudio can normally detect your local Zotero library automatically.

In your Quarto document, switch to Visual mode and choose:

Insert > Citation

The citation dialog can search sources such as:

  • your current bibliography
  • Zotero libraries
  • and many more

Choose Zotero or My Library, search for a reference, select it, and click Insert.

For collaborative projects, Zotero Group Libraries can also be used as citation sources in RStudio.

10.3.2 What is references.bib?

Sooner or later, you will see a file called:

references.bib

A .bib file is simply a bibliography database that Quarto can read. It stores information such as authors, titles, years, journals, and DOIs in a structured format.

You generally do not need to type its contents manually.

When you insert a citation from an external source (e.g. Zotero), RStudio can create references.bib and add the reference for you automatically. Your YAML will then contain a line such as:

bibliography: references.bib

That line simply means:

Use the references stored in references.bib when processing citations.

10.3.3 What is a citation key?

Behind the scenes, every reference has a short identifier called a citation key, for example:

smith2024

In Source mode, citations can therefore look like this:

Smith argues that ... @smith2024

This has been shown previously [@smith2024].

This is discussed in detail [@smith2024, p. 42].

Several studies support this conclusion [@smith2024; @jones2025].

If you work mainly in Visual mode, you usually do not need to type these manually. It is still useful to know what the syntax means when you encounter it.

10.3.4 If Zotero does not appear in RStudio

Open:

Tools > Global Options > R Markdown > Citations

There you can select a local Zotero library, enable group libraries, or connect through the Zotero Web API. The settings menu is still labelled R Markdown, but it also controls citations in Quarto’s Visual Editor.

10.3.5 Two sensible Zotero workflows

For most beginners, the built-in RStudio workflow is enough.

10.3.5.1 Workflow A: RStudio inserts citations for you

Use:

Insert > Citation

and let RStudio add references to references.bib as you cite them. This is best for beginners, students, short projects, and researchers who want the simplest setup.

10.3.5.2 Workflow B: Better BibTeX keeps references.bib synchronized

For a longer paper, you may prefer to let Zotero maintain the entire bibliography file automatically.

A typical workflow is:

  1. install the Better BibTeX extension in Zotero
  2. create a Zotero collection for your paper
  3. export that collection as Better BibTeX
  4. save the export as references.bib inside your RStudio Project
  5. enable Keep updated during export

Zotero/Better BibTeX can then refresh the .bib file when the collection changes.

10.4 Turn the document into an APA 7 paper

10.4.1 Install the packages used in this tutorial

Most recent RStudio installations already include Quarto itself. If File > New File > Quarto Document… works and you can render the document, you do not need to install Quarto separately.

For the R examples in this tutorial, install the packages you need once:

# install.packages(c("apa7", "flextable")) # run only the first time

You only run install.packages() when installing a package, not every time you open the project. Later, inside the paper, you will use library() to load packages that are already installed.

10.4.2 Install apaquarto for this paper

Quarto can create Word, HTML, and PDF documents by itself, but it does not automatically turn them into APA 7 manuscripts. For that, we can use the apaquarto extension. Open the RStudio Project for your paper and run:

apa7::install_apaquarto()

The extension is stored with the project. This is useful because the paper carries its formatting setup with it.

10.4.3 Replace the simple YAML with an APA 7 YAML

Now return to the YAML block at the top of paper.qmd.

A useful APA-style starting point is:

---
title: "The Title of Your Paper"
shorttitle: "Short Paper Title"

author:
  - name: "First Author"
    corresponding: true
    orcid: "0000-0000-0000-0000"
    email: "first.author@example.org"
    affiliations:
      - name: "University of Zurich"
        department: "Department Name"

  - name: "Second Author"
    affiliations:
      - name: "Second University"

abstract: |
  This is the abstract of the paper.

keywords: [keyword1, keyword2, keyword3]

bibliography: references.bib

floatsintext: true

format:
  apaquarto-docx: default

execute:
  echo: false
  warning: false
  message: false

editor: visual
---

Do not try to memorize this block. Copy a working template and change the entries that belong to your paper.

The most important lines are:

  • title: and author: describe the paper
  • abstract: contains the abstract
  • bibliography: points to your bibliography file
  • format: determines the output format
  • apaquarto-docx creates an APA-style Word manuscript
  • floatsintext: true keeps figures and tables near the places where they are discussed
  • execute: gives default rules for how R code should appear in the manuscript
  • editor: visual opens the document in Visual mode by default

10.4.4 Render the APA manuscript

Click Render again.

Instead of an HTML preview, Quarto should now create an APA-style Word document.

Conceptually, your workflow has become:

paper.qmd + references.bib + R code
                  ↓
               Render
                  ↓
          APA-style paper.docx

This is the key workflow to understand before adding more advanced features.

10.5 Structure the document like a research paper

10.5.1 Add the sections of the manuscript

For an APA article, you normally do not start the manuscript text with a # Introduction heading. The title of the paper functions as the heading for the introduction.

A basic manuscript can therefore look like this:

This opening paragraph begins the introduction. The paper title is placed above it automatically.

## Theoretical Background

This is a subsection of the introduction.

# Method

## Participants

## Procedure

## Measures

# Results

# Discussion

# References

apaquarto handles the APA heading formatting in the output. If you are working in Visual mode, you can create these headings using the heading menu instead of typing # or ## yourself.

10.6 Add reproducible R analyses

The next sections are where Quarto becomes more than a writing tool. The goal is to connect the manuscript directly to the analysis.

10.6.1 Add a setup cell

Create an R code cell near the beginning of the document and use it to load packages and data.

A useful setup cell is:

```{r}
#| label: setup
#| include: false

library(tidyverse)
library(tidycomm)
library(apa7)
library(flextable)

data <- readr::read_csv2("data/WoJ_names.csv")
```

The lines beginning with #| are cell options. They tell Quarto how this particular code cell should behave.

Here:

#| include: false

means:

Run the code, but do not show either the code or its output in the finished manuscript.

That is useful for setup code that the reader does not need to see.

10.6.2 The cell options beginners actually need

You will encounter many Quarto options, but these five cover most basic paper workflows:

Option Meaning
eval: false Do not run the code
echo: false Run the code, hide the code, show its output
include: false Run the code, but hide both the code and its output
warning: false Hide R warnings in the rendered document
message: false Hide package and other R messages

Because our APA YAML already contains:

execute:
  echo: false
  warning: false
  message: false

those settings apply to all cells by default. You only need to add a cell-specific option when you want that cell to behave differently.

10.6.3 YAML settings versus cell options

Both use name: value, but they control different things.

  • The YAML at the top controls the document as a whole.
  • The #| options inside a code cell control one particular code cell.

10.6.4 Use project-relative file paths

If your data file is located here:

my-paper/data/WoJ_names.csv

and paper.qmd is located in the main project folder, load the data with:

data <- readr::read_csv2("data/WoJ_names.csv")

This path means:

Starting from my project, go into the data folder and open WoJ_names.csv.

This makes the project much easier to move to another computer or share with collaborators.

10.7 Put analysis results directly into the prose

10.7.1 Calculate values once

Suppose you want to report the sample size and mean work experience in your Methods section. Calculate those values in a hidden cell:

```{r}
#| label: calculate-results
#| include: false

statistics_for_method_section <- data %>% 
  summarize(
    number_participants = n(),
    mean_work_experience = mean(work_experience, na.rm = TRUE)
  )

number_participants <- statistics_for_method_section$number_participants
mean_work_experience <- statistics_for_method_section$mean_work_experience
```

Now the values exist as R objects, stored in the objects “number_participants” and “mean_work_experience”.

10.7.2 Insert those values into a sentence

You can insert an R value directly into prose with inline R code:

The sample consisted of `r number_participants` participants. Mean work experience was `r round(mean_work_experience, 2)` years.

When you render the paper, Quarto replaces the code with the current values.

The advantage is substantial: if the data change, the reported number changes the next time you render. You no longer have to copy a number from the console into Word and hope that you remember to update it later.

10.8 Create tables and figures

10.8.1 Create a publication-ready table

For APA-style Word manuscripts, flextable is particularly useful because it works well with .docx output. The apa7 package provides helpers for APA-style formatting.

For example:

```{r}
#| label: tbl-descriptives
#| tbl-cap: "Descriptive Statistics for Work Experience by Country"

summary_table <- data %>%
  group_by(country) %>%
  summarize(
    M = mean(work_experience, na.rm = TRUE),
    SD = sd(work_experience, na.rm = TRUE),
    N = sum(!is.na(work_experience))
  ) %>%
  ungroup()

apa7::apa_flextable(summary_table)
```

Two lines are especially important:

#| label: tbl-descriptives
#| tbl-cap: "Descriptive Statistics for Work Experience by Country"
  • the label gives the table a stable internal name
  • the tbl- prefix tells Quarto that this object is a table
  • tbl-cap provides the table caption

You can now refer to the table in the text with:

Descriptive statistics are reported in @tbl-descriptives.

Quarto inserts the correct table number automatically.

If the table later changes from Table 2 to Table 3, the reference changes with it.

10.8.2 Create and cross-reference a figure

Figures follow the same logic.

```{r}
#| label: fig-work-experience
#| fig-cap: "Distribution of Work Experience by Country"
#| fig-width: 6
#| fig-height: 4

data %>%
  ggplot(aes(x = country, y = work_experience)) +
  geom_boxplot() +
  theme_minimal() +
  labs(
    x = NULL,
    y = "Work Experience (Years)"
  )
```

The fig- prefix tells Quarto that this is a figure.

Refer to it in the prose with:

The distribution of work experience is shown in @fig-work-experience.

Again, you do not need to type “Figure 1” manually.

10.10 Useful options once the basic workflow works

The sections below are valuable, but they are not required for your first Quarto paper.

10.10.1 Produce more than one output format

One source document can create several output formats:

format:
  apaquarto-html: default
  apaquarto-docx: default
  apaquarto-pdf:
    documentmode: man
    a4paper: true

A practical workflow is to use HTML while writing because it renders quickly, and create Word or PDF when you need a manuscript to share or submit.

10.10.2 Anonymous peer review

apaquarto includes options for masked manuscripts. For example:

mask: true
masked-citations:
  - myownpaper2025
  - myotherpaper2024

mask: true removes identifying author information from the manuscript. References listed under masked-citations can also be masked for review.

Always check the journal’s own instructions because journals differ in what they expect authors to remove.

10.10.3 Reproducible package versions with renv

A .qmd file preserves your R code, but R packages themselves change over time. For important or long-lived projects, renv can record the package versions used by the project.

Install and initialize it with:

install.packages("renv")
renv::init()

After adding or updating packages, record the current environment with:

renv::snapshot()

A collaborator can restore those package versions with:

renv::restore()

You do not need renv to learn Quarto. It becomes useful when reproducibility across computers and over longer time periods matters.

10.11 If you already know a bit Markdown

If you have used R Markdown before, the transition to Quarto is relatively small.

R Markdown Quarto
Create a new .Rmd file Create a .qmd file
Click Knit Click Render
Put many chunk options inside {r, ...} Prefer readable #| option: value lines
Use bookdown for many cross-references Cross-referencing is built into Quarto
Use setwd() in a document Use a project and relative paths
Type “Table 1” and “Figure 1” manually Use @tbl-... and @fig-... references
Copy results from the console into prose Use inline R code when useful
Commonly use papaja in older APA workflows apaquarto provides an explicit Quarto/APA 7 workflow
Use older Zotero-to-RStudio add-ins Use RStudio’s built-in citation integration or Better BibTeX

Existing R Markdown projects do not need to be rewritten simply because Quarto exists. For a new paper, however, Quarto is usually the more convenient starting point.

10.12 Final advice

  1. Render the document frequently. Fixing one small rendering problem immediately is much easier than debugging many problems at the end.
  2. Use Visual mode when it makes writing easier and Source mode when you want to understand or precisely edit the underlying document.
  3. Keep the manuscript, bibliography, data, scripts, and figures inside one RStudio Project. Prefer relative paths over setwd().
  4. Let Quarto handle things it can handle reliably: citation formatting, table and figure numbering, cross-references, and reproducible values in the prose.
  5. For a simple workflow, use RStudio’s direct Zotero integration. For a long-lived paper, consider a paper-specific Zotero collection with Better BibTeX automatic export.
  6. Use .docx when collaborating with researchers who rely on Word comments and Track Changes. The same .qmd source can still create other formats when needed.
